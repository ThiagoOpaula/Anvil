# Step 2 — GUI dependency section + updater uses `deps::build`

> **Execution:** implement via a `general` subagent with model **`deepseek-v4.1-flash`**.

## Goal

1. **GUI Scan tab**: Dependencies section showing the tree + missing/incompat issues.
2. **Updater**: replace the inline incompatibility check with `deps::build`, preserving *"this update would introduce a conflict"* semantics (and extending it to mutual-update conflicts).

Out of scope: drag & drop, profiles, RunSummary schema changes, update-introduced missing-required warnings, blocking updates, CLI flag/config changes, other roadmap items.

---

## Design

Two surfaces, one shared graph:

| Surface | Data | When |
|---|---|---|
| GUI Scan "Dependencies" | `deps::build(&identified_mods)` — **current** install graph | on `ScanComplete` |
| Updater warnings | project all pending updates → `deps::build` → diff vs pre-update graph | after phase 6, before summary table |

## Changes by file

### 1. `src/deps.rs` — two pure helpers

```rust
/// Apply `(project_id, new_version)` replacements onto a clone of `mods`.
/// Unmatched entries unchanged; updates for uninstalled projects ignored.
pub fn project_updates(
    mods: &[IdentifiedMod],
    updates: &[(String, ModVersion)],
) -> Vec<IdentifiedMod>

/// Pairs in `after.incompat` whose `(project_id, conflicts_with_project_id)`
/// key is absent from `before.incompat`. Identity is the id pair, not struct
/// equality — display names can change across versions.
pub fn newly_incompatible(before: &DepGraph, after: &DepGraph) -> Vec<IncompatPair>
```

No new types. No rendering helpers (GUI uses public `graph.missing` / `graph.incompat` + existing `format_tree`).

### 2. `src/types.rs` — additive `ProgressRenderer` method


Same pattern as `report_outcomes` / `is_cancelled`. No `RunSummary` / `ApiClient` changes.

### 3. `src/updater.rs` — replace the inline check

**Delete** `src/updater.rs:367-382` (per-candidate `latest_version.dependencies` loop inside phase 6). Leave the problematic-status warn at `:357-365` alone.

**Add** once after the phase-6 stream (`~:390`), before the phase-7 table (`:392`):

```rust
let before = deps::build(&identified);
let updates: Vec<(String, ModVersion)> = candidates.iter()
    .map(|c| (c.identified.current_version.project_id.clone(), c.latest_version.clone()))
    .collect();
let projected = deps::project_updates(&identified, &updates);
let after = deps::build(&projected);
let introduced = deps::newly_incompatible(&before, &after);

let warnings: Vec<String> = introduced.iter()
    .map(|p| format!(
        "Update introduces incompatibility: {} conflicts with {}",
        p.project_name, p.conflicts_with_name
    ))
    .collect();

for w in &warnings { tracing::warn!("{}", w); }
progress.report_warnings(&warnings);
```

Also: `use crate::deps;`, drop unused `DependencyType` import (`:32`).

**Semantics preserved and improved:**

| Scenario | Old loop | New diff |
|---|---|---|
| New version declares Incompatible with installed mod | warns | warns |
| Conflict already existed before the update | silent | silent |
| Two updates conflict with each other | warns | warns |
| Conflicting target filter-excluded but installed | **missed** (`filtered`) | warns (`identified`) — intentional fix |
| Update introduces missing required dep | silent | silent (out of scope) |

Still warn-only — never block or skip. Runs before the dry-run short-circuit so `--dry-run` still reports.

### 7. `src/gui/app.rs` — section + banner

**State** (near `identified_mods` at `:76`):
```rust
dep_graph: Option<crate::deps::DepGraph>,
update_warnings: Vec<String>,
```

**Lifecycle:**
- `ScanComplete` (`:260-269`) → `dep_graph = Some(deps::build(&identified))`
- every `identified_mods.clear()` (`:324`, `:616`, `:790`) → `dep_graph = None`
- `WorkerEvent::Warnings(ws)` → `update_warnings = ws`
- Check-updates click / Ctrl+U / new scan → `update_warnings.clear()`

**Scan tab — Dependencies section** between Filters (ends `:868`) and the results table (starts `:872`):
- `egui::CollapsingState::load_with_default_open(..., issue_count > 0)` — open when dirty, compact when clean
- Header: `"Dependencies"` or `"Dependencies — N issue(s)"`
- Issues first: missing = `Color32::RED`, incompat = `Color32::YELLOW` (matches banner idiom `:648`)
- Then `deps::format_tree` lines in `ui.monospace` inside a 200px `ScrollArea`
- Graph over **full `identified_mods`** (ignore Scan-tab Filters) — same as `run_list`

Must sit *above* the table: the table consumes `ui.available_height()` (`:885`); anything below it gets squeezed out.

**Updates tab** — yellow `update_warnings` labels at the top of `render_updates_tab` (after heading `:1020`).

## Execution

Implementation is **delegated to a `general` subagent** running **`deepseek-v4.1-flash`** (DeepSeek V4.1 Flash):

1. Spawn `general` subagent with `model: "deepseek-v4.1-flash"` and this plan as the prompt (plus the file:line context above).
2. Subagent implements the file changes + tests exactly as specified, runs `cargo test` / `cargo clippy` / `cargo clippy --features gui`, and fixes any fallout.
3. Parent reviews the diff and test results; no further design changes unless the subagent reports a blocker.
